# v0.1 — Read-only Readiness Scanner (EKS)

**Goal:** `kua scan --cluster prod-eks-01 --region ap-south-1 --target 1.31` produces a trustworthy risk report (Markdown + JSON) explaining what will break, why, and how to fix it before upgrading. Nothing in the cluster is modified.

**Why first:** zero-risk for users to try, fastest to validate, and its output becomes the PR body in v0.2.

**Definition of done for v0.1**
- Scans a real EKS cluster using read-only IAM + read-only Kubernetes RBAC.
- Detects: upgrade path & skew, EKS insights, deprecated/removed APIs, add-on compatibility, drain blockers, capacity/IP issues, compute types that need special handling.
- Captures a metrics baseline reference.
- Deterministic rules produce findings; Bedrock adds a clearly labelled narrative.
- Every step is written to a hash-chained CloudWatch audit stream.
- Report has a snapshot fingerprint.
- Published as a tagged release with a README quickstart.

# v1.0 — EKS GA: Hardening, Fleet Scale, Evals & Publishing

**Goal:** Make `k8s-upgrade-agent` something other teams can adopt with confidence: security-reviewed, provably auditable, fleet-aware, evaluated, packaged, and well documented. It also refactors the provider boundary so v1.1+ adapters slot in cleanly.

**Definition of done**
- Published threat model; IAM/RBAC reviewed against it; all high-risk items mitigated or documented.
- Audit trail exportable to immutable storage and verifiable end to end.
- Fleet scan across AWS Organizations accounts/regions with a consolidated dashboard.
- LLM evaluation suite with golden scenarios gating releases.
- Signed artefacts: PyPI package, container image, Terraform registry module, SBOMs.
- Docs site with quickstart that gets a new user to a first report in under 15 minutes.

## V10-T01 — Threat model & security review

**Antigravity prompt:**
```
Read docs/plan/00-project-context.md and follow its principles. Implement only this task.

TASK V10-T01: Write docs/threat-model.md using STRIDE per component, and open issues for each unmitigated threat.

Components: CLI/scanner, Bedrock reasoner (AgentCore), GitHub App, plans bucket, KMS signing key, Step Functions/Lambda executor, DynamoDB state, audit log, GitHub Actions trigger and gate workflows, Kubernetes RBAC.
Must cover at least:
- Prompt injection via cluster data → LLM (mitigations: sanitiser, forced tool schema, code-side enforcement, LLM has no tools).
- Malicious PR comments / gate spoofing (permission checks, bot/author exclusion, gate-id binding).
- Plan tampering after approval (KMS signature, immutable S3 object, fingerprint).
- Compromised GitHub App key (scoped installation, no merge/bypass, Secrets Manager rotation).
- Confused-deputy on executor role (OIDC sub condition, cluster ARN scoping, tag conditions).
- Log tampering (no Delete permissions, hash chain, Object Lock export).
- Supply chain (pinned deps, signed images, SBOM).
- Data exfiltration to Bedrock (redaction, no secrets read, region pinning, model-invocation logging guidance).
- Denial of service: stuck locks (lease expiry), runaway retries (SFN retry caps).
Each threat: description, likelihood/impact, mitigation, residual risk, test reference (link to tests/security/*). Add a mermaid data-flow diagram with trust boundaries.
```

## V10-T04 — Provider interface v2 refactor

**Why:** v1.1–v1.3 add AKS, GKE and on-prem. Refactor now, while only one provider exists, so EKS assumptions don't leak into the core.

**Antigravity prompt:**
```
Read docs/plan/00-project-context.md (principle 10) and follow it. Implement only this task.

TASK V10-T04: Refactor the provider boundary.

1. Audit kua/core, kua/rules, kua/plan, kua/executor, kua/gitops, kua/verify for EKS-specific assumptions (labels like eks.amazonaws.com/nodegroup, EKS add-on names, AMI concepts, subnet IP math, UpdateClusterVersion). Move each into providers/eks behind interfaces.
2. New interfaces in kua/providers/base.py:
   - ClusterOps: control_plane_version, begin_control_plane_upgrade(to, token) -> OperationRef, poll_operation(ref) -> OperationStatus, list_available_versions() -> list[str].
   - NodePoolOps: list_pools(), node_pool_of(node) -> str | None, create_pool_like(old, new_name, version, taints, labels, token) -> OperationRef, update_pool_taints(pool, add, remove), delete_pool(pool) (optional capability), pool_nodes(pool).
   - AddonOps: list_managed_addons(), compatible_versions(addon, version), upgrade_addon(addon, version, token).
   - InsightsOps (optional): upgrade_insights(target).
   - CapacityOps: capacity_facts(), capacity_rules() -> list[Rule] (provider-specific rules registered dynamically).
   - Capabilities: a set of strings (e.g. {"managed_addons","insights","surge_upgrade","native_bluegreen"}) that planners consult.
   - Provider-specific finding rules live under providers/<name>/rules and register with a provider tag; the engine runs core rules + active provider rules.
3. Keep behaviour identical: all existing tests must pass unchanged (except import paths). Add a contract test suite tests/contract/test_provider_contract.py parametrized by provider fixtures, which v1.1+ adapters must pass.
4. Update architecture docs.
```

## V10-T09 — LLM evaluation suite

**Why:** You can't claim the reasoning is reliable without measuring it — and model changes must not silently regress quality.

**Antigravity prompt:**
```
Read docs/plan/00-project-context.md (principles 1–3) and follow them. Implement only this task.

TASK V10-T09: Build evals/ for the reasoner.

- evals/scenarios/*.yaml: at least 30 golden scenarios, each with sanitized facts input + expectations:
  * must_mention_finding_ids (priority ordering expectations, e.g. API-REMOVED before DRAIN-*),
  * go_no_go expected,
  * forbidden: claims contradicting facts (e.g. saying rollback of CP is possible), recommending force delete / disabling PDBs permanently,
  * injection scenarios: facts containing hostile instructions → output must not comply.
- Graders: deterministic checks first (schema, ids, go_no_go, forbidden phrases via regex), then an LLM-as-judge rubric (separate model call, temperature 0) scoring correctness/helpfulness 1–5 with rationale; judge prompt stored in evals/judge.md.
- `kua eval run --model <id>` produces evals/results/<date>-<model>.json and a Markdown summary; CI job (manual/nightly) fails if deterministic pass rate < 100% on injection scenarios or < 95% overall, or judge mean < 4.0.
- Document how to compare models (cost, latency, score) to pick the default.
```
